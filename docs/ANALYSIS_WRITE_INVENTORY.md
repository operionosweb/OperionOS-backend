# Analysis write-path inventory

This inventory describes local repository code, not a deployed schema. The analysis "worker" is the HTTP-triggered processing execution; there is no durable worker, heartbeat, or automatic recovery. Migration 035 adds a one-time database claim for a queued, ingestion-ready run and the main pipeline now passes its database-issued fence context to the result-write paths. This is local implementation work only; it has not been applied to any hosted database. A run can also be invoked through manual stage routes, which fail closed when writing a run that requires a fence but lack a database-issued context.

The analysis route requires an authenticated organization member with `contract:analyze`. Repositories scope by organization and run in application code; direct PostgreSQL connections and the Supabase service role are privileged. Those application checks and RLS are not substitutes for the database fence. `035 rehearsal` refers to `test/phase88-postgres-rehearsal.js`; it uses a disposable PostgreSQL cluster and exercises the real claim function, fenced transaction helper, clause service/repository, shared-write guards, and stale/wrong-identity rejection. It does not exercise hosted Supabase, live Storage, or every production adapter end to end.

It does not yet execute the complete pipeline across every real adapter or prove hosted role grants/RLS.

## Database and remaining review

Migrations 031-032 write journal/events/outbox and queued run state through service-only RPCs; migration 033 conditionally guards result rows and indirect evidence links; migration 034 adds execution identity and shared-write guards. Migration 035 adds a service-role-only one-time claim, immutable generation-1 ownership, context-required result writes, matching-owner shared contract/aircraft writes, and run-attributed AI usage uniqueness. It is local and unverified on hosted databases. Existing triggers enforce ingestion readiness, state transitions, append-only records and some immutability, but do not fence pre-existing active runs until they receive a database claim. Cascade deletes and administrator/owner privileges remain separate bypass considerations. Ownership transfer, release, heartbeat, renewal, expiry recovery, and retry claims are intentionally disabled.

The separate `routes/supabase/migrations` directory contains older 001-006 supplier, clause, obligation, risk-score, blog and upload definitions; it is not the canonical `supabase/migrations` chain exercised by the rehearsal. Whether those legacy definitions match any deployed database is unverified.

The inventory is not yet proof of complete coverage: dynamic SQL, legacy callers, database functions, hosted roles, authorization and human-operation interactions require continued review. A status marked IMPLEMENTED LOCALLY is not evidence that a migration was deployed or that hosted permissions are correct. A claim expires after 24 hours and cannot be renewed or recovered; such runs can remain blocked for manual review. Do not enable ownership transfer or recovery.
